## 技术要点

### 方案选型

| 备选方案 | 优势 | 劣势 |
|----------|------|------|
| **分布式 RDB**（采用） | 最小改动，原生 SDK 支持，autoSync 自动同步 | 图片文件仅路径同步，需 UI 处理不可用状态 |
| 分布式 KV Store | 更灵活 | 需重构数据层 |
| 分布式 DataObject | 实时对象同步 | 不适合持久化场景 |
| 跨端迁移 (Continuation) | 任务接续 | 不满足"数据同步"需求 |

### 数据流

```
设备A 保存 Clip → RDB.insert (本地 DB)
    ↓ autoSync
设备B RDB.on('dataChange') → loadClips() → applyFilters() → UI 刷新
```

### 图片跨设备限制
- RDB 同步的是**文件路径字符串**，不包含文件内容
- `loadClips()` 时用 `fileIo.statSync()` 检测文件是否存在
- 不存在的图片显示占位提示，点击不执行复制
- 后续可用 `@ohos.request` 或 `@ohos.distributedHardware` 传输图片文件

### 去重窗口延长
- 60s → 300s：分布式场景下设备 A 写入后，设备 B 可能也检测到同一剪贴板变化，延时写入
- 300s 窗口 + `saveSeq` 竞态保护 = 可靠去重

### 权限
- `ohos.permission.DISTRIBUTED_DATASYNC`：`setDistributedTables(DISTRIBUTED_DEVICE)` 所需
- 为 user_grant 权限，首次启动弹窗请求
- 权限被拒 → distributed 设置静默失败，App 正常以本地模式运行
