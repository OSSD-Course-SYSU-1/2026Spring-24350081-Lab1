## 技术要点

### 跨端迁移（Continuation）流程

```
源端（设备A）                          对端（设备B）
─────────                             ─────────
① 用户触发迁移
② EntryAbility.onContinue(wantParam)
   → snapshotToWantParam()
   → wantParam['echo_tab'] = 0
   → wantParam['echo_search'] = 'xxx'
   → wantParam['echo_category'] = 0
   → return AGREE
                                      ③ App 未运行：onCreate(want)
                                         App 已运行：onNewWant(want)
                                      ④ restoreFromWant(want)
                                         → pendingRestore = true
                                      ⑤ Index.checkAndRestoreContinuation()
                                         → currentTab 恢复
                                         → clipboardVM.onSearch() 恢复
                                         → clipboardVM.onFilterCategory() 恢复
```

### 状态桥接架构

```
ClipboardViewModel.onSearch() ──→ ContinuationBridge.searchKeyword
ClipboardViewModel.onFilterCategory() ──→ ContinuationBridge.selectedCategoryId
Index (Tab 切换) ──→ ContinuationBridge.currentTab
                              ↓
          EntryAbility.onContinue() 快照到 wantParam
```

### 数据量控制
- 仅传递 3 个小字段（tab 索引 + 搜索词 + 分类 ID），远小于 wantParam 100KB 限制
- 不传递大数据（剪贴内容、分类列表），由分布式 RDB 的 autoSync 负责

### 与 v7 分布式 RDB 的关系
- **v7（分布式 RDB）**：数据同步层 — clips/categories 表 autoSync
- **v8（跨端迁移）**：任务接续层 — UI 状态（Tab/搜索/筛选）跨设备迁移
- 两者互补：RDB 保证数据一致，Continuation 保证体验连续
